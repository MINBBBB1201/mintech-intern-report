# 캐리어와 쿠폰 기록 검증 실행 결과

2026-10-24에 기록 검증 도구를 구현하고 55개 소프트웨어 시험을 실행했다. 모든 시험에서 기대한 오류 코드가 포함됐고 유효 쌍 수가 예상값과 일치했다. 이 결과의 자료 구분은 SOFTWARE_TEST이며 인턴 당시의 현장 실측이나 체크리스트 도입 효과가 아니다.

## 검증 질문과 방법

체크리스트에서 요구하는 값을 CSV로 옮겼을 때 필수 정보 누락, 기록 중복과 비교 조건 불일치가 드러나는지 확인했다. 정상 입력을 만든 뒤 각 조건을 하나씩 바꾸어 결과를 검사했다. 시험 코드는 AI 도구를 활용해 구현했다.

기본 입력은 AB와 BA 각 한 쌍, 방법별 3개 측정점으로 구성한 12행이다. 각 행은 프로그램이 만든 자료다. 시험 날짜 2000-01-01, TEST로 시작하는 식별자와 두께 값은 고정 시험 상수이며 실제 장비나 인턴십 기록을 뜻하지 않는다.

## 실행 결과

| 시험 범주 | 확인한 동작 |
|---|---|
| 정상 AB 및 BA | 두 쌍을 수용하고 두께 범위 차이 +2 nm와 -2 nm를 계산 |
| 필수값 개별 누락 | 필수 25개 필드를 각각 비웠을 때 해당 쌍의 계산 보류 |
| 식별과 형식 오류 | 중복 ID, 잘못된 날짜, 방법, 순서 및 확인 상태 처리 |
| 수치 오류 | 음수, 소수 오류 건수, 문자열, NaN, 무한대 및 범위 밖 방향 처리 |
| 비교 조건 불일치 | 블록, 레시피, 측정 도구, 실행 정보 및 측정점 집합 불일치 처리 |
| 자료 범주 혼입 | 문헌, 재구성 예시와 소프트웨어 시험을 현장 입력으로 집계하지 않음 |
| 빈 입력과 0 | 빈 파일은 EMPTY로, 실제 숫자 0을 넣은 시험은 유효값으로 처리 |
| 반복 측정 | 같은 측정점이 반복되면 별도 검토로 남기고 범위를 계산하지 않음 |

전체 55개 중 통과 55개, 실패 0개다. 통과 건수는 구성한 입력과 기대 결과를 대조한 값이다. 일반적인 검출 정확도나 현장 오류 감소율은 측정하지 않았다. 시험 결과는 [JSON 원출력](../outputs/software_validation/test_results.json), 시험 입력은 [시험 CSV](../outputs/software_validation/test_cases.csv)에 있다. 소스 해시와 실제 UTC 실행 시각도 JSON에 남겼다.

## 계산과 집계의 선택

두께 범위는 같은 측정점 집합에서만 계산한다. 시험 입력의 한 쌍은 A의 범위 6 nm와 B의 범위 4 nm로 차이 +2 nm이고, 다른 쌍은 8 nm와 10 nm로 차이 -2 nm다. 서로 반대인 두 예제는 계산을 확인하기 위한 값이며 B의 우수성을 가정한 자료가 아니다.

측정점별 시험 상수와 계산 과정은 [수치 예제](validation_example.md)에 정리했다.

오류 건수는 실행 단위 값이다. 측정점마다 같은 건수를 반복 기록해도 실행당 한 번만 집계한다. 한 실행 안에서 오류 건수가 서로 다르면 어느 값이 맞는지 자동으로 고르지 않고 검토 대상으로 남긴다. 좌표는 현재 워크북의 비음수 좌표계를 따르며 방향은 0도 이상 360도 미만이다. 현장 좌표계가 다르면 기준과 도구를 먼저 바꿔야 한다.

CSV의 FIELD_MEASUREMENT 표시는 기록의 진위를 증명하지 않는다. 도구는 파일 구조와 비교 조건을 검사하며 원자료, 측정기 교정과 확인자의 검토를 대체하지 않는다. 현장 입력 파일을 검사한 결과는 [빈 입력 확인 결과](../outputs/software_validation/field_input_check.json)에 별도로 보관했다.

## 재현 방법

기록 검증 도구는 Python 표준 라이브러리만 사용한다.

```bash
python code/verify_records.py --out outputs/software_validation
python code/record_validation.py templates/field_records.csv
```

첫 명령은 시험 CSV와 결과 JSON을 다시 만든다. 두 번째 명령은 원래 현장 CSV를 읽기만 하며 현재 빈 파일에 대해 기록 0건, 유효 쌍 0건과 EMPTY를 출력한다. 검사 결과는 기본 경로인 `outputs/software_validation/field_input_check.json`에 저장한다. 현장 입력에 문제가 있으면 종료 코드는 1이다.

## 다음 단계

기록 도구 외에 비교분석 워크북의 입력 변경 및 통계 계산 47개 검사를 실행했다. 날짜나 오류 건수에 문자를 넣어도 수식 오류 대신 입력 확인 상태와 해당 건수가 표시되는지 포함한다. Artifact Tool에서 수식을 재계산하고 검사했으며 네이티브 Excel 실행 검증은 아니다. 대시보드는 Streamlit AppTest로 기본 필터, 빈 선택, 전체 선택과 표본 수 및 생성 양성률 변경의 4개 동작을 확인했다. 브라우저 화면 배치와 실제 장비 연결을 검증한 결과는 아니다.

현재 실행 결과로 확인한 범위는 기록 검사와 계산 동작이다. 현장 준비 오류 감소, 두께 범위 변화와 회사 적용은 담당 엔지니어의 검토 및 별도 실측으로 확인해야 한다. 실제 자료는 빈 현장 입력 파일에 기록하고 SOFTWARE_TEST 자료와 합치지 않는다.
